# Native gameplay integration probe

`python scripts/run_amiga_gameplay_integration_probe.py` builds `amiga/gameplay_integration_probe.s`, runs it with Copperline on an unexpanded PAL A500 with Kickstart 1.3, and captures a screenshot and 10-second GIF under ignored `build/amiga/gameplay-integration/`. The probe starts from the retained source frame-1299 RAM image after its interrupt tail. The cartridge and generated assembly remain local build inputs, not tracked source.

The executable runs the verified generated scoreboard, input, score, player, ball, movement/sprite, IRQ-counter and deferred-VDP routines, plus the source-semantic native audio tick. It samples Amiga port-2 joystick left/right and CIA fire as decoded game-input bits, schedules source updates at 59.922738 Hz against 50 Hz PAL presentation, and converts the previous source sprite-attribute buffer before constructing the next buffer. The bridge scans all ten source records, preserves source priority while packing visible records into eight Amiga channels, selects the source pattern and colour for each, and updates each Amiga sprite pair palette. The static court, sprite-pattern atlas and score-bank artwork were converted from controlled frame-1310 VRAM. The six scoreboard fields now select native bitplane banks by patching Copper pointers. Source scoreboard VRAM writes still go to a shadow buffer for verification but do not drive the display. PSG and deferred VDP bytes are recorded but have no Paula or display effect yet.

The latest run on the exact target profile assembled a 212,404-byte executable (SHA-256 `49332452784e71c2283f4914d40e29103cac1027a5382baef0e6245e2250f643`). Native logs show 59 source updates by PAL frame 50 and 119 by frame 100. A scripted joystick-left hold moves the lower player state and matching sprite buffer X from `$C0` to `$A3`; the screenshot shows both players and the ball. The native sprite bridge reports no channel, pair-colour or unknown-colour errors at the sampled log points; its active ball slot is 4. The [GIF](../build/amiga/gameplay-integration/gameplay-integration.gif) and [screenshot](../build/amiga/gameplay-integration/gameplay-integration.png) are local ignored artifacts. This is an integration and timing sample, not a full source-capture differential for the live run.

The current image is a captured in-progress game state, not a boot-from-title experience. The sprite atlas and score glyph artwork assume pattern VRAM is unchanged from the controlled frame; live VDP writes are not applied to them. The court remains static. No Paula sound is played, there is no ADF for the live game, and a full match has not been measured for missed PAL deadlines. Next, map the ordered PSG events to Paula output and exercise longer rallies and scoring from a live start state.

## Live serve capture

`python scripts/run_amiga_live_serve_probe.py` holds port-2 fire from emulator second 5 for 2.5 seconds, captures a [screenshot](../build/amiga/gameplay-integration/serve.png) and [10-second GIF](../build/amiga/gameplay-integration/serve.gif), and checks native state against the retained source serve trace. With the frame-1299 initial RAM and its interrupt tail, PAL frames 50, 100 and 150 reach source updates 59, 119 and 179. Their lower-player X and displayed buffer X, ball court Y/X, lower/upper player phase, and active ball slot exactly match source frames 1358, 1418 and 1478 respectively. The ball occupies source slot 4, then slot 0 at the third checkpoint. All eight logged native checkpoints report zero sprite-bridge errors.

The current live executable also selects score graphics directly from game RAM at the source scoreboard routine's draw boundary. It reads the status and score redraw flags before that routine consumes them. A new pending status selects its text, expiration selects blank text even though the low status code remains in RAM, and a pending score redraw selects both points, both game tallies and mode. The 224 Copper pointer pairs are patched during the vertical blank containing that source update. The shadow VRAM writes are not used to choose pixels.

In the scripted serve, native PAL frame 100/source frame 1418 has B point/status selectors 0/0. At PAL frame 150/source frame 1478 they are 1/0. The source awards B's point at 1433, draws point 1 and status 1 at 1434, then clears the timed status at 1465. Screenshots before and after this sequence change pixels in B's point cell, while A's point, both game tallies, the now-blank status and mode stay fixed. The [scored screenshot](../build/amiga/gameplay-integration/serve-scored.png), earlier [screenshot](../build/amiga/gameplay-integration/serve.png) and [GIF](../build/amiga/gameplay-integration/serve.gif) are ignored local artifacts. The live executable is 212,404 bytes, SHA-256 `49332452784e71c2283f4914d40e29103cac1027a5382baef0e6245e2250f643`. This confirms sampled state and scoreboard display selection through one scored point, not full pixel parity or a full match.

The separate [native Copper scoreboard probe](score-copper-probe.md) still checks all 38 prepared values, the baseline capture and an alternate state independently of gameplay.
