# Native gameplay integration probe

`python scripts/run_amiga_gameplay_integration_probe.py` builds `amiga/gameplay_integration_probe.s`, runs it with Copperline on an unexpanded PAL A500 with Kickstart 1.3, and captures a screenshot and 10-second GIF under ignored `build/amiga/gameplay-integration/`. The probe starts from the retained source frame-1299 RAM image after its interrupt tail. The cartridge and generated assembly remain local build inputs, not tracked source.

The executable runs the verified generated scoreboard, input, score, player, ball, movement/sprite, IRQ-counter and deferred-VDP routines, plus the source-semantic native audio tick. It samples Amiga port-2 joystick left/right and CIA fire as decoded game-input bits, schedules source updates at 59.922738 Hz against 50 Hz PAL presentation, and converts the previous source sprite-attribute buffer before constructing the next buffer. The bridge scans all ten source records, preserves source priority while packing visible records into eight Amiga channels, selects the source pattern and colour for each, and updates each Amiga sprite pair palette. The static court and sprite-pattern atlas were converted from controlled frame-1310 VRAM. Scoreboard VRAM writes go to a shadow buffer; PSG and deferred VDP bytes are recorded but have no Paula or display effect yet.

The latest run on the exact target profile assembled a 137,576-byte executable (SHA-256 `c20f91da0b29c2af6136ae896eae80391c252df0e7a5381a3d2f4b0014802cd2`). Native logs show 59 source updates by PAL frame 50 and 119 by frame 100. A scripted joystick-left hold moves the lower player state and matching sprite buffer X from `$C0` to `$A3`; the screenshot shows both players and the ball. The native sprite bridge reports no channel, pair-colour or unknown-colour errors at the sampled log points; its active ball slot is 4. The [GIF](../build/amiga/gameplay-integration/gameplay-integration.gif) and [screenshot](../build/amiga/gameplay-integration/gameplay-integration.png) are local ignored artifacts. This is an integration and timing sample, not a full source-capture differential for the live run.

The current image is a captured in-progress game state, not a boot-from-title experience. The sprite atlas assumes pattern VRAM is unchanged from the controlled frame; live VDP writes are not applied to it. The court and scoreboard glyphs remain static. No Paula sound is played, the shadow VDP writes are not rendered, there is no ADF, and a full match has not been measured for missed PAL deadlines. The next display step is to apply scoreboard tile changes to Amiga bitplanes. After that, map the ordered PSG events to Paula output and exercise rallies and scoring from a live start state.

## Live serve capture

`python scripts/run_amiga_live_serve_probe.py` holds port-2 fire from emulator second 5 for 2.5 seconds, captures a [screenshot](../build/amiga/gameplay-integration/serve.png) and [10-second GIF](../build/amiga/gameplay-integration/serve.gif), and checks native state against the retained source serve trace. With the frame-1299 initial RAM and its interrupt tail, PAL frames 50, 100 and 150 reach source updates 59, 119 and 179. Their lower-player X and displayed buffer X, ball court Y/X, lower/upper player phase, and active ball slot exactly match source frames 1358, 1418 and 1478 respectively. The ball occupies source slot 4, then slot 0 at the third checkpoint. All eight logged native checkpoints report zero sprite-bridge errors. The assembled executable is 137,740 bytes, SHA-256 `9b7eef04a37467659fb7db781d200b7ac64c970915c24c139fff18214ad54576`.

This confirms sampled game state and sprite selection through the captured serve, not pixel equality of the two GIFs. The source serve trace ends at frame 1500; later native states in the GIF have no retained source checkpoint for comparison.

The separate [native Copper scoreboard probe](score-copper-probe.md) now selects pre-rendered Amiga graphics for all six changing scoreboard fields and checks its baseline and alternate captures. That selector has not yet been connected to this live executable's score and status state.
