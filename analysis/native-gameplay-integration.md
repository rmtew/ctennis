# Native gameplay integration probe

`python scripts/run_amiga_gameplay_integration_probe.py` builds `amiga/gameplay_integration_probe.s`, runs it with Copperline on an unexpanded PAL A500 with Kickstart 1.3, and captures a screenshot and 10-second GIF under ignored `build/amiga/gameplay-integration/`. The probe starts from the retained source frame-1299 RAM image after its interrupt tail. The cartridge and generated assembly remain local build inputs, not tracked source.

The executable runs the verified generated scoreboard, input, score, player, ball, movement/sprite, IRQ-counter and deferred-VDP routines, plus the source-semantic native audio tick. It samples Amiga port-2 joystick left/right and CIA fire as decoded game-input bits, schedules source updates at 59.922738 Hz against 50 Hz PAL presentation, and converts the previous source sprite-attribute buffer to Amiga sprite positions before constructing the next buffer. The court bitmap, sprite shapes and pair palettes are currently the converted controlled frame-1310 assets. Scoreboard VRAM writes go to a shadow buffer; PSG and deferred VDP bytes are recorded but have no Paula or display effect yet.

The latest run on the exact target profile assembled a 134,364-byte executable (SHA-256 `0a7d3b1320b20ffc883f71eae7f6793a8985428cf3e2deeafd854285b15674ee`). Native logs show 59 source updates by PAL frame 50 and 119 by frame 100. A scripted joystick-left hold moves the lower player state and matching sprite buffer X from `$C0` to `$A0`; the screenshot visibly shows the moved player. The [GIF](../build/amiga/gameplay-integration/gameplay-integration.gif) and [screenshot](../build/amiga/gameplay-integration/gameplay-integration.png) are local ignored artifacts. This is an integration and timing sample, not a full source-capture differential for the live run.

The current image is a captured in-progress game state, not a boot-from-title experience. Shapes do not yet follow changing SG sprite-pattern numbers; pair palettes and scoreboard glyphs remain static. No Paula sound is played, the shadow VDP writes are not rendered, there is no ADF, and a full match has not been measured for missed PAL deadlines. The next display step is to convert and select all source sprite patterns and changing colours from source data, then apply scoreboard tile changes to Amiga bitplanes while preserving the source's one-update sprite-buffer lag. After that, map the ordered PSG events to Paula output and exercise serves, rallies and scoring from a live start state.
