# Native gameplay integration probe

`python scripts/run_amiga_gameplay_integration_probe.py` builds `amiga/gameplay_integration_probe.s`, runs it with Copperline on an unexpanded PAL A500 with Kickstart 1.3, and captures a screenshot and 10-second GIF under ignored `build/amiga/gameplay-integration/`. The probe starts from the retained source frame-1299 RAM image after its interrupt tail. The cartridge and generated assembly remain local build inputs, not tracked source.

The executable runs the verified generated scoreboard, input, score, player, ball, movement/sprite, IRQ-counter and deferred-VDP routines, plus the source-semantic native audio tick. CIA-B timer B paces source updates at approximately 59.922738 Hz independently of 50 Hz PAL presentation. Each due update samples Amiga port-2 joystick and CIA fire, advances gameplay, and sends sound events to Paula. The sprite bridge prepares the previous source attribute buffer in an inactive Amiga sprite bank, preserving source priority while packing visible records into eight channels. Sprite palette and six scoreboard bitplane-bank selections are prepared in an inactive Copper list. The vblank display commit changes only `COP1LC`; the expensive preparation runs outside blanking. The static court, sprite-pattern atlas and score-bank artwork were converted from controlled frame-1310 VRAM. Source scoreboard VRAM writes still go to a shadow buffer for verification but do not drive the display; deferred VDP bytes have no display effect.

The integration and serve runs on the exact target profile retain approximately 60 source updates per 50 PAL frames; their exact phase against PAL frame counts can differ by a tick between launches because the clocks are independent. A scripted joystick-left hold moves the lower player state and matching sprite buffer X below `$C0`; the screenshot shows both players and the ball. The sprite bridge reports no channel, pair-colour or unknown-colour errors at sampled log points. The [GIF](../build/amiga/gameplay-integration/gameplay-integration.gif) and [screenshot](../build/amiga/gameplay-integration/gameplay-integration.png) are ignored local artifacts. The [long-game report](../build/amiga/long-game/report.json) records the current executable hash and verifies that Copper-list pointer commits finish before visible scanlines in the measured run.

The current image is a captured in-progress game state, not a boot-from-title experience. The sprite atlas and score glyph artwork assume pattern VRAM is unchanged from the controlled frame; live VDP writes are not applied to them. The court remains static. Paula plays source-triggered tone events with a provisional square wave and volume curve; noise output, stereo balance, and complete sound fidelity have not been validated. There is no ADF for the live game. The [long-game replay](long-game-replay.md) checks a game award and ordered sound events. Real-hardware display verification and the after-game callback remain open.

## Live serve capture

`python scripts/run_amiga_live_serve_probe.py` holds port-2 fire from emulator second 5 for 2.5 seconds, captures a [screenshot](../build/amiga/gameplay-integration/serve.png), [10-second GIF](../build/amiga/gameplay-integration/serve.gif), and [stereo WAV](../build/amiga/gameplay-integration/serve-audio.wav), and checks native state against the retained source serve trace. With the frame-1299 initial RAM and its interrupt tail, PAL frames 50, 100 and 150 reach source updates 59, 119 and 179. Their lower-player X and displayed buffer X, ball court Y/X, lower/upper player phase, and active ball slot exactly match source frames 1358, 1418 and 1478 respectively. The ball occupies source slot 4, then slot 0 at the third checkpoint. All seven logged native checkpoints report zero sprite-bridge errors.

The current live executable also selects score graphics directly from game RAM at the source scoreboard routine's draw boundary. It reads the status and score redraw flags before that routine consumes them. A new pending status selects its text, expiration selects blank text even though the low status code remains in RAM, and a pending score redraw selects both points, both game tallies and mode. The 224 Copper pointer pairs are patched in the inactive list during simulation or immediately after a list swap; only the list address changes during blanking. The shadow VRAM writes are not used to choose pixels.

In the scripted serve, native PAL frame 100/source frame 1418 has B point/status selectors 0/0. At PAL frame 150/source frame 1478 they are 1/0. The source awards B's point at 1433, draws point 1 and status 1 at 1434, then clears the timed status at 1465. Screenshots before and after this sequence change pixels in B's point cell, while A's point, both game tallies, the now-blank status and mode stay fixed. The [scored screenshot](../build/amiga/gameplay-integration/serve-scored.png), earlier [screenshot](../build/amiga/gameplay-integration/serve.png) and [GIF](../build/amiga/gameplay-integration/serve.gif) are ignored local artifacts. This confirms sampled state and scoreboard display selection through one scored point, not full pixel parity or a full match.

The [Paula tone path](paula-tone-output.md) plays the same source-triggered three-tone stream. The serve WAV contains a strong approximately 525 Hz tone where the retained source trace writes PSG period `$0D5` (525.17 Hz). The serve script checks that source event and the captured tone, alongside its score, sprite and cadence assertions.

The separate [native Copper scoreboard probe](score-copper-probe.md) still checks all 38 prepared values, the baseline capture and an alternate state independently of gameplay.
