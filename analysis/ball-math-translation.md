# Ball arithmetic translation from the Z80 source

The executable, reviewable translations are [scripts/ball_math.py](../scripts/ball_math.py), [scripts/source_ball_update.py](../scripts/source_ball_update.py), [scripts/source_player_update.py](../scripts/source_player_update.py), and [scripts/source_input_movement.py](../scripts/source_input_movement.py). They operate on a byte array for `$C000-$C0FF`, retain byte/word wraparound, and mutate the fields touched by each named source routine. They use no emulator. [scripts/source_gameplay_slice.py](../scripts/source_gameplay_slice.py) runs the translated input, score, lower-player, upper-player, ball, and movement/sprite routines in ROM order. The full address-ordered update remains in [frame-update-contract.md](frame-update-contract.md).

| ROM | Python function | Exact operation |
| --- | --- | --- |
| `$151E-$152A` | `multiply_151e(H, L)` | Eight shift/add rounds produce unsigned `H*L` in a 16-bit `HL`. |
| `$152B-$1541` | `divide_152b(HL, E)` | Eight restoring-division rounds return 8-bit quotient in `H`, remainder in `L`. Quotients beyond 255 and divisor zero follow the instruction loop instead of raising an exception. |
| `$1542-$1553` | `triangular_root_1542(HL)` | Initial carry subtracts one; the loop subtracts each successive integer twice. Result is the least `k` satisfying `n <= k*(k+1)`, which differs from `floor(sqrt(n))`. |
| `$1554-$1613` | `derive_launch_vector_1554(ram)` | Constructs `$C057-$C059` using setup `$C05A-$C05F` and scratch `$C067-$C06A`. It performs the ROM's multiply/divide/triangular-root sequence, retains intermediate 8-bit subtraction and NEG wrap, then sets horizontal and vertical sign bits. |
| `$136B-$1382` | `_signed_step_136b(field, step)` | Computes `((field & $7F)*step)/$20`, taking the quotient byte and applying 8-bit NEG when the sign bit is set. |
| `$12CE-$136A` | `advance_ball_12ce(ram)` | Increments `$C066`; computes court X/Y from `$C060/$C061`, `$C064/$C065`; computes displayed Y from `$C061/$C062/$C063` and the step; updates `$C034/$C035`, `$C04D/$C04E`, `$C037/$C050`. The negative-height underflow path clears displayed Y and `$C050`. |
| `$1298-$12CD` | `court_contact_1298(ram)` | Uses court X/Y to set the outside-field bit when applicable, advances first/second contact bits in `$C039`, and respects the early return once bit 2 is already set. |
| `$121C-$1286` | `bounce_121c(ram)` | Calls contact-flag update, chooses `$C067/$C068` scaling constants from `$C038`, copies the current court coordinate to the next flight base, rescales height and signed-magnitude X/Y fields, zeros `$C066`, and sets animation bits in both player records. |

The second module adds the implementation boundary surrounding those routines:

| ROM | Python function | Contract and scope |
| --- | --- | --- |
| `$1383-$13B8` | `net_vicinity_1383` | Tests the net crossing once, flips `$C061` sign, writes the alternate reflection constants and next flight base; returns the Z80 carry-equivalent boolean. |
| `$11A0-$121B` | `ball_dispatch_11a0` | Handles launch, active flight, court bounce, net reflection, out-of-area termination, hidden ball and idle paths in ROM priority order. Launch also writes the `$0596` audio-record assignment. |
| `$1770`, `$0BF3/$0F21` | `player_contact_candidate` | Checks side/outcome gates, adjusted player Y/X, shared proximity limits and height. It writes `$C067/$C068` scratch as the Z80 does even if geometry later fails. A 16-bit position add carries from Y into X. The phase dispatcher decides whether an AI or human player enters this shared path. |
| `$0CDA-$0D46`, `$170A-$1753`, `$0BF3-$0CB0`, `$0F21-$0FE6` | `player_contact_0bf3_0f21` and private helpers | For an accepted hit, builds the new launch vector, animation byte and phase/outcome state. Includes AI-specific PRNG decisions and the ROM's `5*seed+1` update. |
| `$0989-$0A78` | `resolve_pending_point_0989` | Handles a pending outcome when `$C03C` bit 6 and `$C039` bit 7 are set: event code, side selection, point/deuce/advantage, game award, redraw and transition flags. Other `$094E` phase branches are outside this function. |

The player module adds both priority-ordered phase dispatchers `$0B29/$0E54`: initial serve-vector copy, attached-ball update, timed serve launch and handoff, animation completion, shared return contact, AI intercept setup, AI tracking and wait-target selection. It retains the original 7-byte serve vectors and five 9-byte threshold/output tables; those constants were checked against the identified cartridge. AI's random retarget sign at `$0DB9` depends on bit 0 of the Z80 refresh register `R`. The function requires that bit as an explicit input on the affected branch rather than inventing an entropy source.

The coordinate step uses quotient truncation, not floating point: `delta = floor((magnitude * step)/32)`, with sign encoded in the field's high bit and arithmetic wrapped to eight bits before adding the base. The displayed-height calculation is less intuitive. It constructs a 16-bit signed value from `$C061`, subtracts `$C062`, adds twice the step, uses the low byte's absolute value, multiplies by the step, and divides by 32. The `$C061=$80` case constructs `$FF00` at `$1306-$1309`, so even a zero magnitude with the sign bit set is not treated as mathematical zero. The implementation preserves that case.

The launch derivation writes scratch fields as part of its contract; callers later reuse these addresses. Moving or removing those writes before the full update is translated could change AI or bounce behavior. Several divisors can theoretically be zero, and the ROM's divider still has a deterministic result. The Python implementation retains its bit loop for those cases.

The input/movement module adds `$0832` mode-dependent combination of the already decoded `$087E/$0887` input bytes, bounded player movement `$1404/$145D`, animation-table selection `$14A7/$14B3`, player sprite records `$10E9`, and ball sprite-slot ordering `$13B9`. Its four tables match the identified ROM. The buffer returned by the frame-body wrapper is the **prior** 40-byte sprite state that `$046F` uploads before the new movement update; the Python code does not write VDP ports.

The translated score/display module [source_score_display.py](../scripts/source_score_display.py) now handles the `$094E` timed phase priority and scoreboard tile writes to a VRAM byte array. [source_irq_tail.py](../scripts/source_irq_tail.py) advances `$06B1` counters and reports pending VDP-register writes. [source_audio.py](../scripts/source_audio.py) interprets all eight command families in `$17C5-$19BB` against the identified ROM and returns PSG port bytes; the first seven-pulse stream and two concurrent stream prefixes match the source bytes and earlier documented outputs. The whole frame-body function retains the previous sprite upload and the extra upload made at the `$0AF4` position reset as separate outputs.

The model remains **incomplete at its hardware boundary**. Raw SG/SC input-port scanning, actual VDP/PSG devices, reset/title/menu behavior and source timing are outside these functions. The exact Z80 refresh-register bit used by one AI retarget branch must be supplied. No emulator was run for this translation. [scripts/check_source_ball_update.py](../scripts/check_source_ball_update.py) checks integer properties, ROM table identity, and representative ball, contact, score, display, serve, AI, input, movement, audio and source-order cases; later source/Amiga comparison must test complete updates and timing.
