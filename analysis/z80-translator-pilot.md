# Z80-to-68000 translator pilot

The local [translator](../scripts/z80268k.py) is adapted from Jean-Francois Fabre (JOTD), [`amiga68ktools` `z80268k.py`](https://github.com/jotd666/amiga68ktools/blob/abc03aabb57ff19c41a9d32317669768c1caf4a4/tools/z80268k.py), pinned to commit `abc03aabb57ff19c41a9d32317669768c1caf4a4`. The import is commit `8ce0278`; subsequent changes are project-specific. The upstream repository has no declared licence in its GitHub metadata, so publication terms need resolution before pushing this copied file to a public repository.

Run `python -W ignore scripts/z80268k.py --champion-source -n -i mot -o mot -c build/translation/champion-raw.68k -I build/translation/z80-support.i --report-output build/translation/report.json build/analysis/champion-tennis-classified.asm` after regenerating the byte-exact annotated source with `python scripts/roundtrip_rom.py`. The adapter keeps the source listing untouched, converts z80asm hex/data syntax in memory, and writes generated outputs under ignored `build/`. It refuses `--no-review` because that would erase unresolved cases. The report hashes the input and output and lists review markers.

The first full-listing pilot parses 2,823 Z80 code lines and 178 data directives. It emits 42 explicit review/error markers, including `im`, SG/SC `in`/`out`, two `jp (hl)` sites, stack-pointer setup, alternate-register/carry-sensitive constructs and flag-liveness warnings. These markers are blockers, not an estimated percentage of correct gameplay. Hardware I/O and interrupt entry must become Amiga adapters. The source uses both direct calls and RAM-based interrupt dispatch; each indirect target needs an explicit translation.

The Motorola output is not assemblable yet. `vasmm68k_mot` first fails inside the upstream Motorola support include at `SET_XC_FLAGS:MACRO`; that include itself says its macros are not up to date. The MIT output has a larger support macro set, but the currently installed vasm binary uses Motorola syntax. The generated code also needs review for 68000-only legality, 8-bit Z80 flags, source stack semantics, Z80 little-endian word accesses and any register aliasing. Do not treat line parsing as semantic translation. The next gate is to repair or replace the Motorola support macros, make all unresolved cases fail at their source locations, assemble a bounded gameplay slice, and compare its RAM with the existing 40-update and 200-update source captures. Only then measure memory and cycles on the unexpanded PAL A500.

## First native generated routine

`python scripts/run_translated_prng_probe.py` extracts the generated `prng_step` body from the full transcode, replaces only its `GET_ADDRESS prng_seed,a0` macro call with the local RAM-address adapter, assembles it with vasm and runs it through Copperline on the exact PAL A500 profile. [The probe harness](../amiga/translated_prng_probe.s) checks the returned byte and stored RAM byte for all 256 possible seeds against `(5*seed+1)&255`. The bounded executable returned zero; its SHA-256 is `28b9efa719da151762d8328d41eadda89b105ff7c601eb303e712c8ead0edb87`. This establishes one generated routine, not the correctness of flags, calls, stack handling or the whole translated game. The macro substitution and expected byte table are generated under ignored `build/translation/` and guarded by the runner.

## Carry and loop pilot

`python scripts/run_translated_multiply_probe.py` extracts the generated `unsigned_multiply_byte` body, supplies the small Motorola macros it uses in [the probe harness](../amiga/translated_multiply_probe.s), assembles it with vasm, and executes all 65,536 ordered 8-bit operand pairs in Copperline. Every returned 16-bit product matches unsigned multiplication on the same PAL A500 profile; executable SHA-256 `0056f43faa26c2f6a2aeff80d896b2557d7807eb736054a756df16806017e418`. This exercises the generated carry branch and eight-round `djnz` loop. The tool had emitted `jne` in Motorola mode; the direct adaptation now preserves Z80 flags around the loop and emits legal Motorola branches. The result does not prove the other flag patterns, memory helpers or the full generated core.

## Restoring divider pilot

`python scripts/run_translated_divide_probe.py` extracts the generated `restoring_divide_byte` body and runs it on the same PAL A500 profile. [The native harness](../amiga/translated_divide_probe.s) compares quotient and remainder with the instruction-faithful source arithmetic for 8,448 selected dividend/divisor pairs, including divisor zero and values around byte and sign boundaries. All pairs match; executable SHA-256 `da529d58d34887bddc8d550d18ae7a3911784f730aac1b36597ffb8867f66ff3`. This is broad sampling, not exhaustive proof of every 16-bit dividend.

The pilot exposed three flag dependencies now repaired in the direct translator adaptation for Champion Tennis Motorola output: Z80 `LD A,H` and `DJNZ` preserve carry where emitted 68000 instructions do not, and the register-packing macro changes X before `ADC HL,HL`. It also exposed a support-macro error: Z80 `CCF` needs X set from the newly inverted C, because the preceding 68000 compare can leave X stale. The probe harness implements the corrected macro; the translator's support definitions now describe the same operation. The full Motorola support include remains incomplete and is not yet assemblable as a whole. Next assemble a larger generated gameplay path and compare source RAM checkpoints, resolving its support macros and explicit review markers as encountered.

## Player input boundary

The generated `normalize_input_for_player_side` routine, which feeds player movement, now passes all 1,024 combinations of every input byte, both player sides, and both mode-bit states on the same PAL A500 profile. Run `python scripts/run_translated_input_side_probe.py`; executable SHA-256 `7911b5318bc9a15b03188f0b41961cf5f0460312ac134fc824f11e053cfd3647`. The direct translator adaptation preserves the Z80 bit-test result across `LD A,C`, because 68000 `MOVE.B` otherwise changes Z before the conditional return. It also emits legal `BTST.L` for this data-register bit test. The test checks the selected direction byte only; the two-player motion path is tested separately below.

## Bounded two-player motion

`python scripts/run_translated_player_motion_probe.py` now runs the generated lower and upper player-motion routines, their shared bound and step helpers, and input-side normalization together. Its native harness maps the source ROM and RAM into a 64 KB virtual Z80 address space and compares both players' Y/X bytes with the instruction-derived source movement model. All 4,096 deterministic cases pass on the exact PAL A500 profile; they vary position, direction, row, mode, IRQ parity, and motion gates. Executable SHA-256 `84a37d592e947126fdada74ebe87387c50e1d7656bc35f62e446e9a49164e732`. The ROM image, generated virtual-memory fixture, case table, and executable stay ignored under `build/translation/`. This proves the bounded motion path against the model, not a captured whole-frame checkpoint. Animation, sprite construction, game-state transitions, and source hardware adapters remain outside this native probe.

## Player animation and sprite construction

`python scripts/run_translated_player_animation_probe.py` executes generated lower and upper animation handlers plus their threshold-table reader. All 2,048 deterministic cases match the source animation flags, counters and descriptor bytes; executable SHA-256 `da73be56253f49ab2fb2b10978b7bb08c5433cd43203973b9ebae1a5425b125e`. This path exposed an upstream translation error in `PUSH IX` / `POP HL`: pushing a 32-bit host pointer then popping a 16-bit value both gives the wrong Z80 address and leaves two bytes on the stack. The Champion Tennis adapter now derives the 16-bit virtual address from the host pointer and virtual-memory base. The three generated occurrences are guarded by a count check.

`python scripts/run_translated_player_sprites_probe.py` executes the generated descriptor lookup and sprite-record constructor for both players. In 2,048 deterministic cases, all 24 player-sprite attribute bytes match the source model; executable SHA-256 `31efbfb7dd08af90f51e518777e69f6a8d4eb34f4dbba335603cdb380f29d16e`. Both probes use the verified local cartridge only in ignored generated fixtures. Their results establish these bounded RAM effects against the source model. The joined player path is tested below; ball placement, scoring, audio and hardware adapters remain open.

## Joined player path against captured updates

`python scripts/run_translated_player_frame_probe.py` replays the 40 captured active-play updates. For each interval, the source model supplies RAM immediately before movement; the native generated lower/upper movement, animation and sprite routines then run in cartridge order. All 256 RAM bytes after those routines match the model on every interval. The 34 position, animation and player-sprite bytes they can write also match the corresponding source cartridge checkpoint for every interval. The source model completes ball placement and the interrupt tail between intervals and checks its full 256-byte RAM against each capture before preparing the next case. The native executable SHA-256 is `5f9cbc883a25343017e46057b10e7a3162aa0079a0ad451cff3010ade4e51850` on the exact PAL A500 profile. This closes the joined player path for this movement capture; the native test does not yet execute the ball-slot placement, scoring, audio or hardware I/O paths. Next extend the generated frame through ball placement, then check the longer serve/flight/point capture.
