# Round-tripped source annotation audit (2026-09-29)

`python scripts/roundtrip_rom.py` consumes the locally configured identified 8 KB cartridge, applies `rom-blocks.def`, `rom-symbols.def`, `rom-literal-operands.tsv`, and `rom-comments.tsv`, then assembles the ignored generated listing at `build/analysis/champion-tennis-classified.asm`. The latest rebuild matches all 8,192 input bytes. The generated file and rebuilt image are not repository inputs.

The generated listing now has **393 semantically named address labels**, with zero `sub_XXXXh`, `lXXXXh`, `helper_XXXX`, or `loc_XXXX` labels. The names came from incoming control-flow references, branch conditions, data consumers, and RAM/VRAM/PSG effects. The source generator also restores **55 reviewed numeric operands** that z80dasm had misleadingly rendered as labels: lengths, VRAM addresses, input row/mask pairs, coordinate offsets, and zero-valued state. In particular, `$081B/$0823` in the two contact paths are arithmetic offsets, not reads from the point-tile records at those ROM addresses. The listing has 147 address-keyed comments. These counts measure source navigation and instruction-level understanding, not full gameplay equivalence. The full partition has 5,765 instruction bytes and 2,427 byte-emitted bytes; direct data-consumer evidence covers 2,413 emitted bytes. Nine inter-vector padding bytes and five final image-tail bytes remain without direct consumer evidence.

The audio pass named and commented the three-record interpreter, all eight command families, envelope table, pitch table, PSG latch construction, and six embedded stream starts. Audit corrections renamed `$199C` as a command fetcher, `$197D` as a PSG volume-latch writer, and `$19BC` as envelope records; the old `$19BC` `audio_stream_data` alias and redundant `$1FDD` first-observed-stream alias were removed. `$C06C` is now `shared_phase_timer` because title and gameplay both use it. `$0890` is `read_menu_selection_bits`, which combines two input groups and is not a raw controller-pair reader.

Reader-facing comments were revised across the complete listing to explain the role of each path in play, display, input, or sound. Numeric state values remain in the instructions and supporting analysis where they are needed for exact translation. Comments qualify interpretations that static source cannot settle, such as the purpose of the startup delay and the physical meaning of some trajectory fields. This is a prose audit, not new execution evidence.

The disassembly is complete as a reproducible **byte-accounted source listing**: every ROM offset is emitted as a decoded instruction or an explicit data byte, every retained generated address label has an operational name, and the remaining 14 bytes are annotated at their exact positions. The nine zero bytes occupy unused space before fixed Z80 RST/IM 1 entry points. The final `00 FF FF FF FF` lies beyond the sixth sound stream's declared eight-byte span. Those placements explain why they are emitted as bytes; no ROM read of them has been established, so they are not assigned invented gameplay roles. A byte-exact rebuild proves coverage and preservation, not that every decoded instruction is reachable in normal play.

- Exact user-facing mode/side labels and all service alternation details still need source-to-display correlation.
- Z80 `R` bit 0 enters an AI retarget sign decision. A port cannot replace it with PRNG output and claim identical trajectories without comparison.
- Audio command meanings are instruction-derived; ordered PSG bytes from representative streams have static checks, but complete playback timing and audible fidelity are not proven.
- Several vector fields have byte-faithful arithmetic but provisional physical names. The Python analogue remains a checking aid, not the authoritative source.
- The current comments cover the main game, input, display, and audio paths at routine/decision granularity. Source-meaning names reflect byte operations and relationships; visual or tennis interpretation remains qualified where the instructions alone do not prove it.

No emulator was run for this audit. The round-trip command fails if an automatic or address-derived placeholder label reappears. Exact update cadence and source/Amiga parity remain later comparison tasks.
