# Native Paula tone output

The live program retains the cartridge's three-channel sound-stream interpreter and its ordered PSG output. After each due source audio tick, `amiga/paula_tone_output.s` consumes those bytes and writes Paula period and volume registers. It does not feed PSG events back into game logic. PSG tone channels 0, 1 and 2 use Paula channels 0, 1 and 3 respectively; Paula channel 2 is unused. The latter mapping places two tones on the left output and one on the right, so stereo balance remains provisional. The source audio interpreter emits no noise-channel events in the retained serve trace; noise output is not implemented.

Each active Paula channel loops the same four signed chip-RAM samples (`127, 127, -127, -127`) with `AUDxLEN=2` words. The PSG tone period is ten bits: its latch byte supplies the low four bits and the following data byte supplies the high six. The port keeps those ten bits per source channel and sets the relevant `AUDxPER`. The [TI SN76489AN data sheet](https://map.grauw.nl/resources/sound/texas_instruments_sn76489an.pdf) gives tone frequency as `3,579,545 / (32 * PSG_period)` Hz. The [Amiga Hardware Reference Manual](https://www.ikod.se/wp-content/uploads/2020/08/Amiga_Hardware_Reference_Manual_1989.pdf) gives the PAL Paula clock as 3,546,895 ticks/s, the audio DMA registers, and a minimum safe DMA period of 123. For four samples per square-wave cycle the exact conversion is `PSG_period * 3,546,895 * 32 / (3,579,545 * 4)`. The 68000 uses the close rational `507/64`, rounds to the nearest integer, and clamps to 123. Its ratio differs by about 0.065% before integer rounding. PSG zero period is treated as 1024.

PSG attenuation values 0–14 select a 64-to-2 Paula volume table approximating the chip's descending level steps; value 15 mutes. The waveform, analogue filtering and stereo placement can differ from an original SG/SC machine. This path deliberately preserves the game sound timing and event order before fine waveform matching.

`python scripts/run_amiga_live_serve_probe.py` checks source frame 1316's PSG channel-2 pitch bytes `$C5,$0D`, giving period `$0D5` and 525.17 Hz. Copperline dumps the live game's 44.1 kHz stereo [WAV](../build/amiga/gameplay-integration/serve-audio.wav); a bounded analysis of its left channel finds that frequency component 24.7 times stronger than the nearby 450/600 Hz checks. The same run passes the sampled sprite, score, and 59/119 update-cadence checks on an unexpanded PAL A500 profile. This proves the source-triggered serve tone reaches native audio at the expected pitch in this captured case. It does not yet establish every sound command, attenuation accuracy, noise effects, stereo balance, or uninterrupted playback over a full match.
