# Long game replay and current boundary

`python scripts/capture_source_long_game.py` captures the cartridge's game callback with one-player fire held from source frame 1300. It records RAM and ordered PSG bytes for 2202 callbacks, including B's points at source updates 134, 469 and 807, and B's game award at update 1204 (frame 2503). The scoreboard consumes that result at update 1205. The capture and cartridge remain ignored under `build/reference/source-long-game/`.

`python scripts/run_amiga_long_game_probe.py --ordinary` builds and runs the native executable on a PAL A500 OCS 68000 with 512 KB chip RAM, no expansion and Kickstart 1.3. It also builds a replay variant, supplies the source's Z80 refresh-bit choices as a private generated fixture, holds native fire, and compares the same game callback. The replay fixture is needed because source AI uses Z80 R bit 0 for target-sign choices; the ordinary Amiga executable samples a changing CIA timer bit mixed with the game PRNG. The source capture's refresh choices are not embedded in the ordinary port.

The replay checks RAM state at native log checkpoints, all four point/game transitions and the following scoreboard selections, the ordered PSG event bytes, and a visible awarded-game tally in the screenshot. It writes `report.json`, `after-game-award.png`, `game-award.gif`, and `game-award.wav` under ignored `build/amiga/long-game/`. The optional ordinary run writes `ordinary-long.png` and measures whether it awards a game without the replay fixture. The report distinguishes exact replay parity from the ordinary run.

The source changes its callback pointer from `$0699` to `$06B1` at frame 2631 after the game. `$06B1` is the shared interrupt tail already used at the end of gameplay updates: it advances counters, schedules sound, and handles pending video-register changes. With it installed alone, gameplay, input, scoring, and sprite construction pause. The cartridge's main-thread menu/round path observes mode bit 5, installs the tail-only callback, waits for the transition counter, changes mode and display state, then restores `$0699`. In this capture the tail-only interval lasts through frame 2766; gameplay resumes at frame 2768. The live executable still calls the gameplay body every source tick, so parity ends at the callback switch. The next translation boundary is the callback routing **and** the main-thread transition, not a new implementation of the `$06B1` tail. The current live loop paces simulation with CIA-B timer B, samples input on each due source update, and sends its sound events to Paula in that update. It prepares inactive sprite DMA data and a separate Copper list containing palette and scoreboard selections. During vertical blank it changes only `COP1LC`; the next list is prepared afterward. The probe fails if that pointer commit finishes on a visible line. The measured long replay and ordinary run both had zero such late commits. This does not yet prove glitch-free display on WinUAE or real hardware, nor a complete match.
